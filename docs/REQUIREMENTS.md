# v0.2.1 产品需求与验收

## 目标和范围

面向使用 Claude Code、Codex 或 WorkBuddy 的 Mac 用户，用一个稳定的小入口回答两个问题：工具是否在工作/需要我处理？订阅还有多少额度？

包含 macOS 刘海状态、可独立开关的工具和菜单栏额度、日／周／月 Token、API 费用估算与对应趋势。无服务端、Windows/Linux、多设备同步。

## 交互合同

| 场景 | 展示 | 操作 / 退出条件 |
|---|---|---|
| 无任务 | Claude 左、Codex 右，轻微空闲动作 | 各侧单击打开各自客户端 |
| 单工具运行 | 左 logo、右侧三个点；Claude 间歇轻跳，Codex 旋转 | 整条单击跳转；运行状态不清除 |
| 双工具运行 | 左 Claude、右 Codex，各有自己的状态 | 各侧独立点击 |
| 同工具多任务 | 已完成/总数，例如 `1/3`；计数轻微过渡 | 按会话去重；等待协助优先问号，全完成显示勾 |
| 需要协助 | 淡金色小问号，无圆框、无文案 | 只有回答/继续执行/终止/新指令替代才能解除；点击不是回答 |
| 已完成 | 静止 logo + 薄荷绿细线勾 | 具体会话已读后清除该会话；工具持续前台约 1–2 秒后清除该工具已有的完成提醒，不修改客户端已读数据 |
| 查看额度 | 双击将刘海本身展开为用量与额度面板 | 再次双击或面板失焦收起；悬停无展开 |

Claude 与 Codex 都启用时，左侧 Claude、右侧 Codex 的快捷入口始终保留，各自独立显示运行、等待、完成或闲置状态。一方有任务不隐藏另一方的闲置入口；入口数量由启用设置决定，只有仅启用一个工具时才使用单工具布局。闲置额度继续遵循显示开关。

收起的任务条高度保持不变，宽度按当前实际可见内容计算：单/双工具、额度开关、额度位数和多任务计数变化都相应伸缩。左右外边距一致且留出轮廓安全空间；有实体摄像头时，两翼独立伸缩，摄像头避让区保持固定，不强制两翼等宽；无实体刘海时不保留摄像头空白。图标动画不参与尺寸计算。不显示任务文案，不增加第二行，不滚动文字。真实摄像头遮挡区域不可排字。单击延迟 350ms 用于区分双击；键盘 Enter 立即打开。

额度图标为彩色，数字为剩余百分比，取已知窗口的最小值。面板显示各窗口与重置时间。网络错误保留明确标记的历史值；无数据为 `—`。

“任务完成通知”和“需要协助通知”分别开关，新安装默认开启；旧配置关闭完成通知时，新增协助通知迁移为关闭。关闭某类通知只清除该类当前及排队项，重新开启不补旧事件，不影响任务状态。协助通知按会话、轮次及问题调用去重，初次观察的等待作为基线不弹；部分回答保留其他请求，点击、关闭或超时不算回答。协助排队优先、8 秒收起，完成沿用 5 秒，悬停暂停。

## 状态优先级与边界

1. 同工具存在多会话：等待协助优先；已观察到的完成先临时显示勾，同工具仍有任务时满 8 秒让位给进度（例如 1/2），不得将让位视为已读。没有后续任务或全部完成时，完成勾保留至对应工具访问/会话已读，不因 24 小时到期清除。工具独立计数；未查看的本轮完成可以与后续新任务一起计数，启动前历史完成不加入。
2. 完成需要明确轮次完成信号；启动历史、文件没变化、进程消失、主动中断不是成功。
3. 已确认的完成不可被同一条旧记录再次弹出；新轮次能重新显示。
4. 回答与问题按调用 ID 和问题索引对应；部分回答不清空其他未答问题。
5. 读取失败不上传内容、不输出原始日志，最多保留活动 30 秒，然后空闲。已观察到的 Codex 待协助问题持续跟踪，不受普通任务的日志新鲜度窗口影响。
6. 锁屏隐藏窗口；显示器变化后按实际硬件重新定位。
7. 系统“减少动态效果”禁用装饰动画。
8. 点击工具或通知打开客户端失败时，接住同步启动异常、异步失败和超时；仅显示通俗的手动打开/重启 Mac Notch 指引，不展示技术堆栈，也不把未知原因一律说成未安装。提示未关闭时不叠加，所有工具共用 30 秒提示间隔；冷却期间仍允许新的打开尝试，同工具请求未结束时忽略重复点击。失败跳转不算已查看，不主动清除对应通知。

## 人工验收

- 内置真实刘海及无刘海外接屏：空闲/运行/等待/完成分别截图，确认边界不抖动、不盖住摄像头。
- Claude 真任务与 Codex 真任务，双工具同时执行，核对动画及左右位置。
- 发起一个异步问题，等待至少一个扫描周期，回答后确认问号退出；多问题仅回答一项不得误退出。
- 多个会话完成后只查看其中一个，具体会话已读信号只清除对应项；单击或 Cmd-Tab 返回工具并持续前台约 1–2 秒，会清除该工具已有的完成提醒，但另一工具的提醒、运行中和待协助状态保留。
- Codex 本地未读列表移除对应线程、Claude 对应会话 lastFocusedAt 在完成后增长，才确认具体完成项已查看。这些具体会话信号缺失时，使用工具持续前台访问作为提醒消除规则。
- 校验菜单栏百分比与官方订阅页面同一时刻、同一窗口口径。
- 代理失效、未登录、401、429、锁屏、多屏切换均不崩溃。

自动测试不替代以上屏幕和真实账号验收。构建完成也不意味着已签名、公证或发布。

## v0.2 新用户与窗口规则

- 有实体刘海时优先使用内置刘海屏，状态条 y 等于屏幕顶部；使用非激活 panel 和 enableLargerThanScreen 避免 macOS 菜单栏约束下移。
- 展开内容放在摄像头下方，同一窗口中不存在第二条覆盖面板标题的状态条；悬停不展开，Escape / 失焦收起。
- 首次启动和再次打开应用进入居中的工具设置；所有开关立即生效、自动保存，不设保存按钮，关闭窗口后仍保留选择。Claude、Codex 分别开关并持久化，全部关闭后隐藏刘海，保留退出菜单栏图标；重新打开 Mac Notch 应用进入设置。
- UI 删除网络代理、sessionKey 输入；保留旧配置兼容。Claude 无登录时指导运行 CLI 并完成订阅登录，不承诺启动命令即一定有额度。
- 只读本地历史：日／周／月 Token、API 标准费率估算与按工具堆叠趋势。订阅剩余额度独立展示，不以 Token 反推。

## 控制页、手势与更新

- 空闲额度新安装默认开启，旧配置的明确关闭保留；数值未知仍显示 `—`。
- 右击默认打开控制页，双击展开用量与额度面板；“交换右击与双击”原子交换两者并显示提示，不能保存冲突映射。单击依旧打开工具。
- 控制页沿用原有深色工具卡片与即时保存机制，内容在主区域滚动。两类通知的 PNG 预览由 `scripts/notification-previews.js` 使用生产组件与演示数据生成；预览按钮不创建任务、不跳转真实会话。
- 更新入口手动检查 Mac Notch 自己的 GitHub Releases。体验版可接收体验版及正式版，正式版只接收正式版；草稿、旧版本、架构缺失不冒充可更新。
- 下载对应架构 DMG，校验发布摘要或 SHA256SUMS 后允许打开；失败清除临时文件。仅下载安装包，由用户完成安装，不自动替换应用或修改系统安全设置。

- 协助通知正文展示当前请求中尚未回答的问题，复用纯文本清理和截断；部分回答更新同一通知，不重置计时或重新提醒。Codex 支持同步/异步提问；没有正文的状态信号使用通用提示，不从历史回复猜测。

两类通知均以会话标题作为标题，后接与刘海条一致的完成勾或协助问号；长标题截断时保留图标。正文继续显示本轮结果或实际待回答的问题。通知展开时隐藏顶部任务条的勾和问号，收起后按真实任务状态恢复；缺失标题时显示对应工具的“会话”占位。

通知展开后的顶部图标与正文共用卡片 16px 左边距，右侧工具/状态靠右侧同等边距；中间继续避让摄像头，不沿用收起条相对于摄像头的水平偏移。通知收起后恢复内容自适应宽度与原有图标位置。

通知关闭/到期后，原生窗口保留当前尺寸，卡片轮廓、正文淡出与图标归位在约 240ms 内同步过渡，结束后保留原生画布，透明区域鼠标穿透；过程中不隐藏顶部内容。新通知、展开用量面板、锁屏或屏幕几何变化可取消旧动画，旧回调不得收掉新通知。系统开启“减少动态效果”时直接完成收起；渲染回调异常时主进程应兜底结束过渡。

额度／用量面板收回单行刘海时采用相同的窗口交接：面板内容和背景渐隐、轮廓连续收拢；收起结束时不移动或缩放原生窗口，保留画布并对可见区域之外启用鼠标穿透。关闭按钮、Escape 和失焦共用收起逻辑；收起中重新展开不得被旧动画回调关闭。

## WorkBuddy 与工具数量

- 可选 Claude、Codex、WorkBuddy，最多同时启用 2 个。WorkBuddy 默认关闭，旧配置保留原有两个工具；开启第三个时明确提示先关闭一个，不自动替换。保存入口拒绝三选全开；非法旧配置读取时保留 Claude/Codex、关闭 WorkBuddy。允许只启用一个或全部关闭。
- 任意两工具保留独立快捷入口，按 Claude、Codex、WorkBuddy 的顺序排列。WorkBuddy 点击打开官方客户端，不承诺跳到具体会话。
- WorkBuddy 只读 `.workbuddy/projects` 与 `.workbuddy-ai/projects` 的本地记录；明确 assistant completed 且已观察到同一轮运行才显示完成。incomplete、静默、文件消失都不算成功；AskUserQuestion 按 callId 跟踪，只有对应工具结果或新用户轮次/终止才解除。未记录为该工具调用的授权弹窗暂不推断。
- 本机 Token 按响应 messageId 去重，包含工具调用响应和 reasoning；未维护对应模型价格时显示未定价 Token，不把 0 美元当实际账单。订阅额度使用官方客户端可读的本机登录和受限 billing 请求；加密登录信息明确标记不可读，不尝试绕过加密。
- Mac Notch 与 Token Monitor 使用一致的完成勾规则：单任务保留，多任务完成约 8 秒后让位且保留计数；前台持续访问清除对应工具的完成提醒。

三个工具使用已确认的拟人表情：空闲眨眼/眯眼，运行保持各自节奏，等待协助双眼看向用户并轻抬头招呼，完成昂头微笑；多任务新增时睁眼并出现右上角 ✦。固定 22px 图标盒，表情与位移不参与布局测宽。完成动效只播放一次，额度刷新和 DOM 重绘不重播；多任务数量增加可重新触发惊讶。遵循系统减少动态效果，隐藏窗口不持续重绘。

## 设置面板与空闲额度示意

- 设置面板默认 520 × 820，尺寸不超过主屏幕可用区域减 32 像素；内容可滚动。设置面板显示时显示 Dock 图标，隐藏或关闭设置时隐藏 Dock 图标，后台刘海继续工作。
- 空闲剩余额度开关下展示关闭与开启的真实组件截图；使用固定演示额度并明确标注，不读取用户账号来生成素材。
