# v0.2.1 体验版验证记录

## 2026-11-03 通知收起连贯性（开发阶段）

- 用户反馈通知收回时不连贯。原逻辑先瞬间缩小原生窗口，随后隐藏正文并重排图标；测量期间还会隐藏整个顶部。改为主进程保留卡片窗口、渲染层在 240ms 内同步收拢轮廓/淡出正文/移动图标，再通过带序号的 IPC 完成原生窗口缩小，并在 resize 绘制前重设局部坐标。
- 新通知/面板/锁屏/屏幕变化可取消过渡，旧回调必须匹配当前序号；600ms 兜底避免窗口永久停在展开尺寸。系统“减少动态效果”使用零时长过渡。连续状态消息不得将收起中的顶部切回通知布局。
- 回归发现从通知切回双工具空闲额度时，目标条可能比原卡片更宽，旧实现会取消动画且留下页面过渡状态；现为新旧轮廓保留窗口并集，图标按屏幕坐标连续归位，测量取消时同步清理页面状态。`--smoke --foreground-motion-smoke` 提供该连续通知/前台抑制边界的快速回归入口。
- `npm run verify`：93 项测试通过；117 项既有生产 DOM/原生窗口布局检查通过。最终打包版完整 `--smoke` 返回 `ok: true`，包括中间轮廓变化、顶部不闪空、新通知打断、减少动态效果和前台抑制。逐帧采样取得 48 帧，其中 30 帧处于收起过渡；最后动画帧与第一个收起帧的图标屏幕横坐标均为 744pt，原生窗口约在 262ms 时缩小。采样为本机隔离合成场景，不代替用户主观流畅度验收。
- 本地包：`dist/notification-motion-preview/mac-arm64/Mac Notch.app`；包内 9 个相关运行文件与源码一致，arm64、ad-hoc 签名和 Koffi FFI 检查通过。逐帧数据/中途截图在 `/tmp/mac-notch-motion-packaged-smoke/`。未发布、未替换 `/Applications` 安装版。
