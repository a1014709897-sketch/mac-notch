# 从定制原型到独立产品

1. **最初起点**：Token Monitor 提供本地任务和额度展示，用户将菜单栏图标改为彩色，并希望 Claude 桌面版也能驱动刘海。
2. **状态适配**：Claude Desktop busy/waiting 可用，但 idle 不能直接视为完成；通过同一轮次的完成计数变化补足。Codex 同步提问之外，增加异步 accepted/逐项回答关联。
3. **交互收敛**：完成提醒保留直到查看。最初按客户端前台状态判断，最新细节收敛为会话级已读，避免查看一个会话就清空其他完成项。单击命中区扩大，双击打开额度，取消悬停展开。
4. **失败的文案实验**：曾加入完整文案、缩写、滚动文字、第二行，实际验收不合格。测量确认内置屏幕有真实摄像头遮挡。最终用户明确取消文案，恢复无文案单行。本项目不继承这些失败布局代码。
5. **协助残留修复**：一个已回答问题清除后，旧布局选择题仍处于 pending。新的普通指令现在替代旧选择题，系统上下文不算用户回答。
6. **独立提取**：不复制整个应用并隐藏页面。仅保留有限适配模块与图标；窗口、状态聚合、菜单栏、设置和打包独立。升级 Token Monitor 不再影响本项目代码。
7. **许可证与身份**：保留 MIT 源码声明，不使用上游 bundle ID、自动更新地址、签名或配置目录；产品名称暂定 Mac Notch。客户端标识只用于集成识别。

8. **首发前同步的最新细节**：同工具多任务显示已完成/总数，数字轻微过渡；需要协助时问号优先，同时仍有任务执行则继续图标动画。查看完成项按会话扣除，未查看项、运行项和待协助项继续保留。

本期以稳定、小范围、能核验为目标。所有新的视觉方案都应先在 demo 模式回归，不再直接替换用户日用程序来试排版。

9. **v0.2 独立产品回归**：修正普通窗口被菜单栏挤下的问题；首次工具选择；取消独立额度弹窗，改为同一个刘海表面展开。用户明确扩展范围至今日 Token 和 7 天用量，因此增加独立只读 Worker；不引入上游完整仪表盘。
